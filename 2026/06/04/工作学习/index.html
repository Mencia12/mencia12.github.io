IpAccessListController

· 代码中硬编码了 Nacos 配置的三要素（坐标）：

  • Data ID: IP_ACCESS（代表黑白名单数据存储在该项中）

  • Namespace: nebula_system（命名空间）

  • Group: nebula.system（分组）

注入的四个核心服务互分其责：

  • ConfigInfoPersistService：Nacos 底层用于从数据库（如 MySQL/Derby）直接读取持久化配置信息的服务。

  • ConfigOperationService：Nacos 用于发布、更新配置的核心业务服务。

  • IpAccessService：作者自定义的本地业务服务，处理更深层的复杂业务（如更新逻辑）。

  • ApplicationEventPublisher：Spring 自身的事件发布器，用于异步通知系统其他组件。

1. publishAccessIpConfig（新增 IP 接口）

这是提供给前端的 POST 请求接口。当管理员想要把一个新 IP（或新网段）加入黑名单或白名单时，由该方法负责接收，并在写入前进行防重复和防冲突的严密安全检查。

通过 configInfoPersistService.findConfigAllInfo 捞取密文配置，调用 EncryptionHandler.decryptHandler 解密并由 Jackson 工具还原为内存模型；在写入前，通过 checkIpAlreadyExists 执行同类名单去重，通过 checkIpIsConflict 调用 IPMatcherUtils.isConflict 实现子网掩码级别的黑白互斥校验，最终委托给 ipAccessService.publishAccessIpConfig 执行全量重加密与覆盖。

详细业务流程：

查找数据：方法启动后，首先根据特定的坐标（Data ID, Group, Namespace）去 Nacos 存储库里把当前的整个黑白名单配置文件找出来。

解密与反序列化：拿到的数据在数据库里是加密的。程序先调用 Nacos 安全插件进行解密还原出明文 JSON，再通过 Jackson 工具将 JSON 转换成 Java 内存对象（IpAccessEntity）。

同类名单防重校验：调用 checkIpAlreadyExists 方法。如果要加黑名单，就去已有黑名单里找；如果要加白名单，就去已有白名单里找。一旦发现这个 IP 已经存在，立刻终止流程，报错返回。

对立名单冲突校验：调用 checkIpIsConflict 方法。如果要加黑名单，偏去白名单里撞击；如果要加白名单，偏去黑名单里碰撞。防止同一个 IP 既被封禁又被放行。如果发生冲突，立刻终止并报错。

委托写入：两大安全校验全部通过后，将新 IP 和老名单整体打包，丢给底层的 ipAccessService.publishAccessIpConfig 方法去执行真正的序列化、加密和全网发布。

2. getAccessIpConfigs（查询名单列表接口）

这是提供给前端管理后台的 GET 请求接口。用于完整读取当前系统处于生效状态的黑白名单列表，供管理员查看。

详细业务流程：

抓取密文：直接调用 Nacos 底层的持久化持久层服务，把名为 IP_ACCESS 的配置实体从数据库里整体拉出来。

动态解密：从配置实体中提取出它的专用加密钥匙（encryptedDataKey），然后把密文内容和钥匙一起喂给解密处理器，在内存中还原出最原始的 JSON 字符串。

格式转换：如果明文不为空，用 JSON 解析器把它组装成结构化的 IpAccessEntity Java 对象。

吐出结果：最后将这个包含完整黑名单、白名单列表的对象包装成标准响应体，发送给前端进行表格渲染。

3. updateAccess（修改 IP 配置接口）

这是提供给前端的 PUT 请求接口。用于修改已经存在的 IP 规则，比如将打错的一个 IP 修改为正确的 IP，或者调整其启用/禁用的状态。

详细业务流程：

接收变更意图：接口接收前端传来的旧 IP、新 IP、名单类型以及是否启用的开关状态。

直接透传委托：由于修改逻辑涉及老数据的定位和覆盖，属于核心业务逻辑，Controller 层不作过多停留，直接将所有参数原封不动地透传给底层的 ipAccessService.updateAccessConfig 方法去处理。

4. deleteAccessConfig（删除 IP 名单接口）

这是提供给前端的 DELETE 请求接口。当某个恶意 IP 惩罚期满需要解封，或者某个特权 IP 需要收回权限时，调用此接口从名单中抹去该 IP。

方法在内存中利用 List.removeIf 精准剔除目标 IP 后，重新计算数据密文，并手动伪造、组装了 Nacos 官方的 ConfigForm 与 ConfigRequestInfo（带入 RequestUtil.getRemoteIp 审计信息与 casMd5 乐观锁），最后强调用底层的 configOperationService.publishConfig 接口强推上云，并同步抛出 Spring 本地事件 IpListCheckEvent。

详细业务流程：

拉取并解密老数据：与新增接口类似，先去 Nacos 数据库把当前的黑白名单大 JSON 捞出来，通过密匙解密成 Java 对象。

内存精准剔除：进入 switch 分支判断。如果前端要删的是黑名单，就去 blackList 集合里，利用 Java 8 的高阶函数，把所有与目标 IP 相同的字符串整块抹掉；如果是白名单则去 whiteList 里抹除。

数据重加密：数据被剔除后，将残余的名单重新转成全新的 JSON 字符串。接着判断原配置有没有老密钥，没有就重新算一套密文和新密钥，确保数据库中的敏感数据永远是合规的密文。

组装官方契约表单：手动创建一个官方的 ConfigForm（填入 DataId、新密文等）和 ConfigRequestInfo（通过网络工具抓取是谁、在什么操作应用、哪台机器上发起的删除请求，并带上防并发覆盖的乐观锁标记 casMd5）。

引擎发布与全网同步：把表单强推给 Nacos 核心发布引擎。一旦引擎返回成功，说明 MySQL 已经修改完毕，且全网长轮询开始广播。

抛出本地事件：紧接着在当前服务器内部发布一个 IpListCheckEvent 事件，通知本机的网关拦截器“黑名单减员了，立刻刷新内存”，实现零延迟响应。

5. checkIpAlreadyExists（同类名单防重校验私有方法）

功能描述：
这是一个内部辅助的纯逻辑判断方法。专门用来检查管理员正在添加的 IP，是不是已经在现有的名单列表里了，防止数据冗余。

详细业务流程：

判断名单类型：读取输入参数，如果当前准备加的是【黑名单】（type 1），就获取老数据里的整个黑名单 List。

遍历比对：用一个 for-each 循环去遍历这个 List，拿每一个老 IP 和新输入的 IP 进行字符串全等比较（.equals()）。

返回结果：只要撞上一个完全一样的，说明已经存在了，立刻返回 true（代表有重复）；如果全部遍历完都没找到，说明是新数据，返回 false。

6. checkIpIsConflict（对立名单互斥碰撞私有方法）

这是该系统中最具备网络安全思维的内部私有校验方法。它负责执行黑白名单的“交叉碰撞”，阻止同一个 IP 或网段同时拥有“放行”和“封禁”两种矛盾的属性。

详细业务流程：

如果你正在提交一个【黑名单】（想要封禁它），该方法偏不看黑名单，而是去抓取现有的【白名单】集合。

如果你正在提交一个【白名单】（想要放行它），该方法就去抓取现有的【黑名单】集合。

高级掩码网段碰撞：
拿到对立面的名单集合后，开始循环遍历。这里调用了 IPMatcherUtils.isConflict(新IP, 老IP) 工具方法。

例子：白名单里放行了 192.168.1.0/24（代表这个网段的 254 个 IP 全放行）。现在管理员因为疏忽，想把 192.168.1.5 抓进黑名单。IPMatcherUtils 内部会进行子网掩码计算，敏锐地发现 .5 已经被包含在 .0/24 的网段里了。

触发警报：一旦工具类计算出包含或重叠关系，该方法立刻判定为“产生冲突”，返回 true，从而在前端拦截下这次错误的配置提交。

心跳机制

在微服务架构中，服务实例可能因为：

  • 服务宕机
  • 网络异常
  • 机器重启
  • 容器退出

导致实例不可用。

如果注册中心不能及时感知服务状态，那么消费者仍会调用已经下线的实例，造成请求失败。

Nacos采用客户端主动发送心跳的方式维护服务实例状态。客户端通过BeatReactor定时发送心跳，服务端通过ClientBeatCheckTask定时检查实例健康状态，并自动摘除超时实例，从而保证注册中心中的服务列表始终保持准确和可用。

一、什么是事务（Transaction）

事务（Transaction）是数据库管理系统中的一个重要概念，它表示一组操作作为一个不可分割的整体执行。事务中的所有操作要么全部执行成功，要么全部执行失败，不允许只完成其中的一部分。

事务主要用于保证数据的一致性和完整性。

100 元凭空消失，数据发生错误。

因此需要事务保证：

  • 两步全部成功，则提交事务（Commit）
  • 任意一步失败，则撤销之前所有操作（Rollback）

事务最核心的一句话就是：

要么全部成功，要么全部失败。
